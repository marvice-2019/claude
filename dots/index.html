Dots is how Marvice runs AI agents in parallel. It's built on Munder Difflin, an open-source desktop harness. It wraps the coding CLI you already pay for (Claude Code, Codex, Gemini and more) and puts each session at a desk on a shared office floor. Agents share memory, message each other, and report to one orchestrator agent you talk to.

How the floor works

01

Every terminal is an agent

Each claude, codex or gemini session runs as a real process with its own working folder and identity. You see the raw terminal, unchanged.

02

The hive coordinates them

Agents read shared memory and drain a mailbox. A router moves messages between them, and the orchestrator assigns work and escalates to you only when needed.

03

Memory carries over

Plain-markdown memory with a semantic index. Agents remember what they learned in past sessions and recall it instantly.

Team setup in 5 steps

  1. Install at least one agent CLI

    Claude Code is the default and our standard. If a CLI is missing, the app shows an Install card in the agent's terminal and runs the installer for you.

    npm install -g @anthropic-ai/claude-code

  2. Sign in with your Marvice seat

    Sign in inside the app's terminal with the account Marvice assigned you. Agents run on that plan's hourly limits, so don't use personal accounts for client work.

  3. Run the onboarding wizard

    First launch walks you through it. When it's done, you land on the floor and the orchestrator takes the corner office automatically.

  4. Give every agent its own folder

    Use Add agent and point each one at a single repo or client folder. One agent per job keeps context small and output reviewable.

  5. Check prerequisites

    Settings → Prerequisites lists anything still missing. Local models (Ollama, LM Studio, vLLM) and your own API keys go in Settings → AI Engines.

House rules

Credentials stay out of prompts

Never paste client passwords, API secrets or payment details into an agent. Use environment variables and .env files that are git-ignored.

A human reviews before anything ships

Agents open branches and PRs. They don't push to main, deploy, or send client-facing messages without a person approving.

One client per agent

Don't mix client workspaces in one agent's folder or memory. It prevents data crossing between accounts.

Stuck? Ask in the team channel

Post the agent's terminal output and the step you're on. Most install issues are a missing CLI or an expired sign-in.
